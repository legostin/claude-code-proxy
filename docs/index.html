An HTTPS debugging proxy inside Claude Code

Wirepane intercepts and decrypts the HTTP and HTTPS traffic of your browser, the iOS Simulator, an iPhone, the Android emulator or an Android phone. Every request lands in a filterable list, and Claude reads the same traffic, so "why does login return 401?" gets answered from the real request and response.

Why

Debugging a mobile or web client usually means a separate proxy app, a certificate dance on every device, and copying requests into the chat by hand. proxy keeps all of it where you already work.

No separate app

The proxy, its certificate authority and the request list live in Claude Code, behind /proxy.

One click for a browser

A separate Chrome, Edge, Brave or Chromium window whose whole traffic goes through the proxy, localhost included, with no certificate to install.

Simulators set up for you

The CA goes into every booted iOS Simulator with one button; the Android emulator or a USB phone is pointed at the proxy, and back, with another.

Claude sees the traffic

Two tools hand the model the request list and any request in full: headers and decoded bodies.

Features

  • MITM HTTPS proxy with per-host certificates from a CA made on your machine; plain HTTP, WebSocket upgrades and server-sent events pass through.
  • A filter language: method:POST status:4xx host:*.example.com type:json is:error -text.
  • A tree view: requests grouped by host and path, with request and failure counts on every node.
  • The exact proxy address for each client, the Mac's Wi-Fi address picked over VPN tunnels and VM bridges, and a QR code a phone scans to get the certificate.
  • Request detail with pretty-printed JSON and gzip, brotli, deflate and zstd decoded; Copy as curl and To prompt.
  • Certificate trouble made visible: a client that refuses the proxy certificate, because the CA is not trusted or the app pins certificates, shows up as a CERT row.
  • A setup page served by the proxy at http://claude.proxy/ with an iOS .mobileconfig, an Android .crt and a .pem.
  • Safe on the network: in lan mode phones can use it, but nothing on the network can reach this Mac's localhost through it.
  • Tracked domains per session: decrypt and record only your app's hosts, wildcards included; everything else passes through untouched, so a phone's own services keep working.
  • One-press setup: pick an iOS simulator and it boots with the CA and the system proxy on; pick an Android emulator and it starts behind the proxy; Claude Code itself keeps working.
  • A rules engine: delays, throttling, mocked answers, rewritten headers, URLs and JSON bodies, status codes, dropped connections and scripts, chained by priority.
  • No dependencies: a Node.js sidecar and openssl.

Rules: change requests and responses

Ask Claude in plain words, "make GET /api/feed take 3 seconds" or "answer POST /login with a 500", and it writes the rule into the project's .claude/proxy-rules.json. The proxy applies it at once. The Rules view lists every rule with what it does in words, turns rules on and off, and changes their priority; every matching rule applies, in order.

{ "id": "slow-feed",
  "match": { "methods": ["GET"], "path": "/v1/feed*" },
  "request":  [{ "type": "delay", "ms": 2000 }],
  "response": [{ "type": "setStatus", "status": 503 },
               { "type": "mergeJson", "json": { "error": "down" } }] }

Before sending

Delay, throttle, set or remove headers and query, send elsewhere, rewrite the URL or body, answer with a mock, drop the connection.

On the response

Delay, throttle, set the status, change headers, replace or merge into the JSON body, drop the connection.

Scripts when needed

A JavaScript step for anything else, run only once you approve it, so a cloned repository cannot run code unasked.

Set up a client

ClientHow
A separate browserSetup → Browser → Open Google Chrome (or Edge, Brave, Chromium): its own profile, --proxy-server, localhost captured, and trust by SPKI hash instead of a keychain entry.
iOS SimulatorPick one and press Use: it boots, gets the CA, and the macOS system proxy points at the proxy, with Claude Code's own traffic left alone.
iPhone / iPadListen on LAN, scan the QR code to install the profile, trust it, set the Wi-Fi proxy to the address the tab shows.
Android emulator / USB phoneStart through the proxy launches an AVD with -http-proxy; Android → proxy points a running emulator or a USB phone, and is reverted when the proxy stops.
Android phone on Wi-FiListen on LAN, scan the QR code to get the certificate, set the Wi-Fi proxy; apps need a network_security_config, which the tab copies.
curl, Node, Python, GoHTTPS_PROXY, NODE_EXTRA_CA_CERTS, SSL_CERT_FILE, REQUESTS_CA_BUNDLE, copied from the macOS / CLI tab.

Install

Requires macOS, Claude Code 2.1.292 or newer, and openssl (built into macOS). The proxy runs on Node.js 18 or newer, which it finds by itself; with none, the pane offers to install it. At the Claude Code prompt:

/plugin install wirepane --marketplace legostin/claude-code-proxy

Answer y to add the marketplace and pick a scope, then run /proxy.

FAQ

Is it a replacement for Proxyman, Charles or mitmproxy?

For everyday debugging of what an app sent and what came back, yes, without leaving Claude Code. Rules cover rewriting, mocking and throttling; there are no interactive breakpoints, HTTP/2 or gRPC.

Do I have to install the certificate on my Mac?

Not for the separate browser, which trusts the proxy by SPKI hash. Safari, native macOS apps and the iOS Simulator need the CA trusted; the setup tabs give the commands.

Why do some requests show CERT?

The client refused the proxy's certificate: its CA is not trusted yet, or the app pins its certificates. Finish the setup steps, or add the host to Hosts not to decrypt.

Does my traffic leave my machine?

Only for the servers it was going to anyway. The proxy listens on 127.0.0.1 unless you choose lan, recorded requests stay in ~/.claude/proxy-mod, and Claude reads a request only when it calls the tools; then that request is part of the conversation.

Limits

  • Clients are offered HTTP/1.1 only, so gRPC over HTTP/2 does not get through.
  • WebSocket frames are not decoded; an upgrade shows as one row.
  • The system proxy is put back on stop, at the session's end and when Claude Code quits; only a kill -9 of the proxy can leave it on.
  • Mods are an early-access Claude Code API.
